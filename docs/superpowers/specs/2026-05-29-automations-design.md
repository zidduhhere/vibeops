# Automations — Full Execution Engine Design

**Date:** 2026-05-29  
**Status:** Approved  

---

## Overview

Extend the existing automations panel (toggle-only) into a fully functional AI execution engine. Each automation can run in **agentic mode** (sends emails autonomously) or **supervised mode** (holds output for user review). Gmail Push Notifications (Pub/Sub) trigger automations in real-time when new emails arrive.

---

## Data Model

### `automation_configs` (new)
Per-user configuration for each automation.

| Column | Type | Description |
|--------|------|-------------|
| `id` | uuid | PK |
| `user_id` | text | FK → user_profiles(id) |
| `automation_key` | text | Matches key in user_automations |
| `mode` | text | `"agentic"` or `"supervised"` |
| `trigger_params` | jsonb | Dynamic per automation type (e.g. `{ delay_days: 3, keywords: ["pricing"] }`) |
| `ai_prompt` | text | Custom AI instructions written by user |
| `tone` | text | `"professional"`, `"casual"`, or `"friendly"` |
| `gmail_filter` | text | Gmail search query to scope which emails trigger this (e.g. `label:leads`) |
| `created_at` | timestamptz | |
| `updated_at` | timestamptz | |

Unique constraint: `(user_id, automation_key)`

### `automation_runs` (new)
Execution log for every automation invocation.

| Column | Type | Description |
|--------|------|-------------|
| `id` | uuid | PK |
| `user_id` | text | FK → user_profiles(id) |
| `automation_key` | text | Which automation fired |
| `status` | text | `"pending"`, `"sent"`, `"held_for_review"`, `"failed"` |
| `trigger_email_id` | text | Gmail message ID that triggered this run |
| `trigger_email_subject` | text | Subject line for display in UI |
| `ai_output` | text | Full text generated by AI |
| `sent_at` | timestamptz | When email was sent (agentic mode) |
| `error_message` | text | Error detail if status = failed |
| `created_at` | timestamptz | |

RLS: users can only read/write their own rows.

### Existing: `user_automations`
Unchanged — continues to store enabled/disabled state per automation per user.

## Execution Layer

### Gmail Push Notification Setup

When a user enables any automation (or connects Gmail), register a Gmail Push Notification:
- Call Gmail API `users.watch()` with a Google Cloud Pub/Sub topic
- Pub/Sub topic forwards messages to `/api/webhooks/gmail` via HTTP push subscription
- Store the `historyId` and `expiration` per user — Gmail watches expire every 7 days, must be renewed

### Webhook Route: `POST /api/webhooks/gmail`

1. Decode the base64 Pub/Sub message to extract `emailAddress` and `historyId`
2. Look up the user by email address
3. Call Gmail API `users.history.list()` from the stored `historyId` to get new messages
4. For each new message, fetch full email content
5. Check which of the user's enabled automations match this email (keyword scan, gmail_filter match)
6. For each match, invoke InsForge serverless function `run-automation` with:
   ```json
   { "user_id": "...", "automation_key": "...", "email_data": { "id": "...", "subject": "...", "body": "...", "from": "..." } }
   ```
7. Update stored `historyId` to latest

### InsForge Serverless Function: `run-automation`

1. Fetch `automation_configs` for `(user_id, automation_key)`
2. Fetch user's Gmail OAuth tokens from DB
3. Build AI prompt: combine automation's `ai_prompt` + tone instruction + email content
4. Call OpenRouter (using user's provisioned key or app-level key) to generate reply/action text
5. Insert row into `automation_runs` with status `pending`
6. Check `mode`:
   - **Agentic**: Send email via Gmail API using stored OAuth tokens → update run status to `sent`
   - **Supervised**: Update run status to `held_for_review` — surfaces in VibeOps inbox
7. On any error: update run status to `failed`, store `error_message`

### Gmail OAuth
Reuses existing Gmail OAuth tokens already stored from the Gmail integration. No new auth flow required.

## UI

### Automations List (existing, enhanced)

- Each card gains a **"Configure" button** (gear icon) in the footer alongside the category badge
- Cards show run count from live `automation_runs` data (replacing hardcoded `runs` values)
- Mode badge on each card: "Agentic 🤖" or "Supervised 👁️" (or "Not configured" if no config yet)

### Config Slide-Over Panel (new)

Right-side slide-over, full height. Opens when "Configure" is clicked.

**Header section:**
- Automation name + description
- Enabled toggle (syncs with `user_automations`)
- Mode switcher: two large pill buttons — "Agentic 🤖" and "Supervised 👁️"
  - Agentic: "AI sends emails automatically"
  - Supervised: "AI drafts, you approve before sending"

**Trigger params section:**
Dynamic fields per automation type:
- `auto_draft_pricing`: keyword tag input
- `proposal_followup`: number input for delay days
- `weekly_status`: day-of-week picker
- `invoice_reminder`: number input for days after invoice
- `scope_creep_detector`: no params (always on for all client emails)
- `lead_qualification`: no params

**AI Instructions:**
- Textarea: "Custom instructions for the AI" (placeholder: "e.g. Always mention our agency name, keep replies under 3 sentences")
- Maps to `ai_prompt` column

**Tone selector:**
- 3 pill buttons: Professional / Casual / Friendly

**Gmail filter:**
- Text input: "Scope to Gmail label or search query"
- Placeholder: `label:leads` or `from:@client.com`
- Maps to `gmail_filter` column

**Run history table:**
- Last 10 runs from `automation_runs`
- Columns: Date, Trigger email subject, Status (color-coded badge), View button
- "View" opens a modal showing full `ai_output` + option to send (supervised mode only)

**Footer:**
- Save button (upserts `automation_configs`)
- "Run now" button — manually triggers the automation against the last matching email (for testing)

### New API Routes Needed

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/automations/config` | GET, POST | Fetch/save automation_configs |
| `/api/automations/runs` | GET | Fetch run history per automation |
| `/api/automations/send` | POST | Send a held_for_review run (supervised mode) |
| `/api/automations/run-now` | POST | Manually trigger an automation |
| `/api/webhooks/gmail` | POST | Gmail Pub/Sub push endpoint |

## Error Handling

- Failed runs log `error_message` and show in run history with a red badge
- Gmail watch expiry: a daily cron checks and renews watches within 24h of expiry
- If OpenRouter call fails: mark run as `failed`, do not send
- If Gmail send fails: mark run as `failed`, preserve `ai_output` so user can manually send

---

## Out of Scope

- Multi-step automation chains (automation A triggers automation B)
- Custom automation creation (beyond the 6 hardcoded types)
- SMS or Slack actions (Gmail only for now)
- Analytics dashboard for automation performance
